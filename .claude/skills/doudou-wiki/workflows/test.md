# Test 工作流

对知识库做健康检查，发现问题并给修复建议。

> 📌 **路径约定**：`raw/`、`gen/`、`wiki/` 均指当前知识库（`<project>/kb/`）下的绝对路径，
> 由 SKILL.md 路由时确定（`KB_RAW`、`KB_GEN`、`KB_WIKI`）。`KB_LANG` 为该知识库的语言设置。

## 工作流程

### 1. 运行确定性检查脚本

**先跑脚本**，拿结构性问题：

```bash
python3 <skill-dir>/scripts/check.py --wiki-dir <KB_WIKI> --raw-dir <KB_RAW> --gen-dir <KB_GEN> --json
```

`derived_file` 之类的路径字段按知识库根解析（`raw/x` → `KB_RAW/x`，`gen/x` → `KB_GEN/x`）。
不传 `--gen-dir` 时按 `<raw-dir>` 的同级 `gen/` 推定，该目录不存在会打一行提示。

脚本覆盖这些确定性检查：

| 级别 | 检查项 |
|------|--------|
| P0 | 断链（`[[link]]` 指向不存在的页面） |
| P0 | `[[raw/...]]` / `[[gen/...]]` wikilink 误用（应用普通 Markdown 链接） |
| P0 | Frontmatter 完整性（必填字段、type 合法性） |
| P0 | index.md 与实际文件一致性（双向） |
| P0 | source 页缺 `raw_file`，或 `raw_file` 指向的原件已不存在 |
| P0 | source 页缺 `derived_file`（每份素材都有产物，纯文本也有） |
| P1 | `derived_file` 指向的中间产物不存在（可重跑复原） |
| P1 | 双向链接完整性（A→B 则 B→A） |
| P1 | 孤岛页面 |
| P1 | entity/concept/analysis 缺 `sources` 字段 |
| P2 | `raw/` 中存在但未收录的素材 |

脚本输出作为 P0/P1 的基础，**不要重复检查脚本已覆盖的项目**。

三类溯源问题性质不同，别混着处理：

| 问题 | 性质 | 处理 |
|------|------|------|
| `missing_raw_file` / `missing_derived_file` | 字段本身没写，溯源链断了 | P0，补字段。产物真不存在就先重跑 convert |
| `raw_file_missing` | 原件被删或改名 | P0，问用户是原件移走了还是该删掉这个摘要页 |
| `derived_file_missing` | 产物被清（如清过 `gen/`） | P1，重跑对应路线即可复原，属可自动修 |

`missing_derived_file` 是 P0 而非 P1：产物是 LLM 构建该页时的实际读取来源，
字段缺失意味着这页的内容来源无从查证 —— 与产物文件被清掉是两回事。

### 2. LLM 补充检查

在脚本结果之上，补**脚本查不了的**语义问题：

#### P1 — 质量

- **语言一致性**：按 `KB_LANG` 检查每页主体内容是否用了目标语言。列出不一致的页面，
  给批量翻译选项（确认后逐页翻译，保留 frontmatter 和 `[[链接]]` 不变）
- **矛盾检测**：扫所有 `> ⚠️ 矛盾` 标记汇总已知矛盾；同时找不同页面间未标记的互相矛盾陈述
- **缺失页面**：被 3 次以上 `[[引用]]` 但没有独立页面的概念/实体
- **陈旧信息**：`updated` 超过 30 天且有更新素材引用同一主题的页面
- **空白区块**：页面中有 `_待补充_` 或空章节
- **转写疑点积压**：统计所有 `（转写待核）`、`（原件此处不可辨）` 标记。同一素材上积了 3 处以上，
  建议换参数重转（换 OCR 语种、给 STT 补术语 prompt）而不是逐处人工核对

#### P2 — 建议

- **缺失交叉引用**：内容相关但没互链的页面
- **标签不一致**：同一概念用了不同标签名
- **可合并页面**：内容高度重叠的页面
- **新页面建议**：基于现有内容建议创建的概念/实体页
- **数据空白与知识扩展**（用 WebSearch）：
  1. 找出明显的信息缺口（被多页引用但缺乏深度的主题）
  2. 用 **WebSearch** 搜该领域的最新进展、关键论文、权威资源
  3. 每条输出：缺口描述 + 推荐来源（标题 + 链接）+ 建议优先级

  ```
  🔍 知识扩展建议（基于 web search）:
  - [[memex]] 提到了 Ted Nelson 的超文本但无详细内容
    → 推荐: "Ted Nelson and the Xanadu Project" (https://...)
    → 优先级: 中
  ```

### 3. 生成报告

```markdown
## Wiki 健康检查报告 (YYYY-MM-DD)

### 📊 统计
- 总页面数: N
- 素材摘要: N（其中 音频 N / 文档 N / 图片 N / 文本 N）
- 实体页面: N
- 概念页面: N
- 分析页面: N
- 中间产物: N 个（gen/）

### 🔴 P0 - 需要修复
- [ ] 问题描述 → 修复方案

### 🟡 P1 - 建议改进
- [ ] 问题描述 → 改进方案

### 🟢 P2 - 可选优化
- [ ] 建议描述
```

### 4. 执行修复

- P0 建议立即修复，请求用户确认
- P1 逐项确认
- P2 仅作建议

`derived_file_missing` 这类可自动修的，直接说明「重跑 doudou-xxx 即可复原」并在用户确认后
按 [convert.md](convert.md) 重转。

修复后更新 `wiki/log.md`。

## 注意事项

- 检查不删任何页面，只建议合并或更新
- 问题很多时分批展示，避免信息过载
- 每次 test 后在 log.md 记一条结果摘要
- **`gen/` 不做内容质量检查** — 那层是技能输出的原样缓存，要改就重跑，不手改
