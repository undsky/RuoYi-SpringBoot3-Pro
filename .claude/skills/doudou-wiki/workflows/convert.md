# Convert 工作流

把素材文本化，从 `KB_RAW` 读原件、往 `KB_GEN` 写产物。既是 `convert` 子命令本身，
也是 `add` 的第 3 步（add 直接引用本文档，不重复写一遍）。

**所有素材都要过这一步，包括纯文本。** `gen/` 是 LLM 构建知识库时唯一的默认读取面，
少一份产物就少一条能读的素材。

> 📌 **路径约定**：`raw/`、`gen/`、`wiki/` 均指当前知识库（`<project>/kb/`）下的绝对路径，
> 由 SKILL.md 路由时确定（`KB_RAW`、`KB_GEN`、`KB_WIKI`）。

## 核心原则

1. **本技能不做格式转换** — 一律交给 doudou-doc / doudou-ocr / doudou-stt，参数细节由它们自己的 SKILL.md 决定。
   唯一自己动手的是纯文本的编码归一化（`scripts/derive_text.py`），那不是格式转换
2. **每份素材都有产物** — 纯文本也要归一化进 `gen/`，读取面不留缺口
3. **原件只读** — `raw/` 下的文件永不修改；产物只往 `gen/` 写，绝不写回 `raw/`
4. **产物可复现** — 中间产物统一落 `gen/`，删掉能重新生成，不算知识资产
5. **一个失败不拖垮整批** — 单份素材转换失败就跳过它并记账，继续下一份

## 工作流程

### 1. 扫描与分派

```bash
python3 <skill-dir>/scripts/scan.py --raw-dir <KB_RAW> --wiki-dir <KB_WIKI> --gen-dir <KB_GEN> --json
```

用户指定了文件就加 `--file <文件名>`；要重转已收录的素材就加 `--all`。
省略 `--gen-dir` 时脚本按 `<raw-dir>` 的同级 `gen/` 推定，显式传更稳妥。

脚本对每份素材给出：

| 字段 | 用途 |
|------|------|
| `route` | `text` / `doudou-doc` / `doudou-ocr` / `doudou-stt`，按扩展名一对一确定 |
| `raw_path` | 原件绝对路径，传给处理技能作输入 |
| `derived_file` | 产物的知识库根相对路径（`gen/<slug>.<ext>`），**写进 frontmatter 用这个值** |
| `derived_path` | 产物的绝对落点，**传给处理技能用这个值** |
| `route_script` | 该路线的脚本相对路径（`text` 路线指向本技能自带的 `derive_text.py`） |
| `slug` / `source_page` | 摘要页文件名，add 阶段用 |
| `needs_rename` | slug 里含非 ASCII 字符，需译成英文 slug |
| `warning` | 如超过 100MB 上传上限（`text` 路线不受此限） |

四条路线都有 `derived_file`，都要产出产物 —— 没有「跳过转换直接读原件」这种情况。
`unknown[]` 里的素材扩展名不认识、`derived_file` 为 `null` —— 用 AskUserQuestion
问用户按哪类处理，或跳过。

### 2. 检查处理技能可用性

`text` 路线用本技能自带的脚本，不依赖外部技能，这一步与它无关。

路由结果的 `processors` 字段已给出三个技能的探测结果。只关心**本批素材实际用到**的技能：

- 都可用 → 继续
- 缺了某个，但本批没有它负责的素材 → 不必提
- 缺了本批需要的 → 告诉用户缺哪个技能、负责哪类素材、有几份素材因此跳过，其余照常处理

### 3. 逐份转换

**优先用 Skill 工具调用**对应技能，把这几件事讲清楚：要转哪个文件（`raw_path`）、
产物存到哪（`derived_path`，即 `KB_GEN` 下的绝对路径）、需要什么格式。

三个技能都支持 `-o` / `--output` 指定输出路径 —— 必须用它把产物导到 `KB_GEN`，
否则会落到技能自己的 `resources/` 目录里，知识库这边拿不到。

Skill 工具不可用时，用 `processors.<name>.script` 的绝对路径直接跑脚本兜底。

各路线的调用要点 —— **只列本工作流的额外要求，参数细节看各技能自己的 SKILL.md**：

#### text（纯文本，本技能自带）

不调外部技能，直接跑本技能的脚本：

```bash
python3 <skill-dir>/scripts/derive_text.py \
    --raw <raw_path> --out <derived_path> --json
```

- 产物扩展名沿用原件（`a.md → gen/a.md`，`b.txt → gen/b.txt`）
- 内容一字不改，只统一编码（GBK / UTF-16 → UTF-8）和行尾（CRLF → LF）
- 返回的 `source_encoding` 若不是 UTF-8，说明原件是别的编码，在摘要页不必特别注明 ——
  归一化是无损的
- `empty: true` 说明原件是空文件，跳过收录并告知用户

#### doudou-doc（办公文档 / 电子书）

- 产物是 Markdown，存成 `gen/<slug>.md`
- 大文件（CSV、长报表）传 `--max-chars`，避免转出的 Markdown 撑爆上下文；
  收录场景 5 万字够用，超出部分在摘要页注明「原件更长，已截断」
- **不接 PDF** —— PDF 一律走 doudou-ocr

#### doudou-ocr（图片 / 扫描件 / PDF）

- 产物是纯文本，存成 `gen/<slug>.txt`
- **PDF 全归这里**，不分有没有文字层：有文字层的它走文字层直抽（不到 1 秒），
  扫描件才真跑识别（首页约 7 秒 + 每多一页 4 秒）
- **PDF 传本地路径，不传 URL**（传 URL 实测会漏行，还慢十几倍）。手上只有 URL 就先下载到 `raw/`
- 非中英素材必须显式指定语种（日、韩、繁体、俄、阿拉伯等）；素材语言不明时先按 `ch` 试，
  结果明显不对再换语种重跑
- 识别结果为空但退出码 0 → 图太小/太淡，在摘要页注明「原件文字不可辨」

#### doudou-stt（音频 / 视频）

- **收录用纯文本**（`-f txt`），不是字幕：wiki 要的是内容不是时间轴
- 中文素材必须传 `--prompt`，否则整篇没有标点，没法读也没法摘要
- 多人对话（访谈、会议、播客）加 `--diarize --show-speaker`，保住「谁说的」这层信息
- 耗时是音频时长的 0.7~1.2 倍，长音频先告诉用户预计要等多久
- 若同时想要字幕，另存一份 `.srt` 到 `gen/`，但 add 只读 `.txt`

### 4. 失败处理

路线是一对一确定的，**没有回落分支** —— 一条路线失败就是失败，不要改走另一个技能硬试。

| 情况 | 处理 |
|------|------|
| 单份素材转换失败 | 标记该素材跳过，记下 stage 和原因，继续下一份 |
| 报 `auth`（400/401） | 该技能的 `.env` 缺 uuid。**一次性告知用户**去对应技能目录配 `.env`，本批凡走该技能的素材全部跳过，不要每份重试一遍 |
| 报 `download` | 远程 URL 取不到，让用户先下载到 `raw/` 再收录 |
| 连不上 API | 该技能的服务地址不通，同 `auth` 处理：一次性告知，跳过整类 |
| 超 100MB 上传上限 | 不要硬传（会干等到超时），告知用户先压缩或分片 |

### 5. 汇总

```
📥 转换完成 4/5
   doudou-stt  interview.mp4 → gen/interview.txt (12,431 字)
   doudou-doc  report.docx   → gen/report.md (3,205 字)
   doudou-ocr  scan.pdf      → gen/scan.txt (1,890 字，3 页扫描件)
   text        notes.md      → gen/notes.md (842 字)
   ⏭️ 跳过     archive.7z    — 扩展名未识别
```

`convert` 子命令到此结束；作为 add 第 3 步时，带着产物继续走 add 第 4 步。

## 注意事项

- 产物**只是中间层**，不是知识资产：`gen/` 默认已在 `kb/.gitignore` 里，删了重跑即可。
  它是 LLM 的读取面，但不是需要长期保管的东西 —— 知识资产在 `wiki/`
- 转换产物**不要直接当摘要页用** —— 逐字稿和 OCR 文本都又长又碎，add 阶段要重新组织。
  纯文本的产物尤其容易让人想直接拷进 wiki，别这么干
- 纯文本产物与原件内容一致，看着像冗余拷贝。它换来的是读取面单一：add 不必按素材
  类型分辨读哪层，`test` 也能对所有素材一视同仁地查 `derived_file`
- 同一素材重复 convert 会覆盖已有产物，这是预期行为（重转通常就是为了拿更好的结果）
- 转写质量存疑的地方（人名、术语、数字）在摘要页标 `（转写待核）`，别在 `gen/` 里改
  —— 那层要保持与技能输出一致，方便重跑对照
