# 豆豆页面设计与复刻

## 目标

把模糊的页面想法、参考网址或现有产品截图转化为目标项目中可运行、可维护、可验证的页面。设计质量不只看静态相似度，还要看信息层级、交互反馈、响应式行为和与现有项目的融合程度。

## 安全与边界

- 参考公开网址时，只提取布局、交互模式、色彩关系、字体层级和可复用的设计规律。
- 不复制第三方品牌标志、商标、完整文案、头像或其他能让页面冒充真实组织/服务的身份元素；必要时用中性占位内容替代。
- 不实现钓鱼登录、凭据收集、支付欺骗、绕过访问控制或未经授权的数据抓取。
- 如果用户要求完整冒充某个真实网站或收集真实用户敏感信息，说明不能照做，并改为提供中性风格参考实现。
- 不把“复刻”理解为照搬源码；只在用户明确授权且目标是自有项目时检查本地代码。

## 工作流

### 1. 先确认输入和目标

读取用户当前项目上下文，不要一开始就写代码。确认以下事项；已有答案直接沿用，缺失项用合理默认值并简短说明：

- 工作目录：当前项目中的 `doudou-vue3/`、`doudou-uniapp/` 文件夹，或用户指定的其他目录。
- 页面入口：新增路由/页面，还是修改现有页面；桌面、移动端，还是两者。
- 内容与状态：页面要展示什么，哪些按钮/表单/列表需要可交互。
- 参考材料：网址、截图、设计稿、已有组件，或没有参考材料。

如果有网址，先获取页面可见结构与设计特征；如果无法访问，不要猜测细节，向用户索取截图或描述。不要将远程页面代码、私密数据或第三方受限内容直接复制进项目。

如果没有网址或设计稿，先给出 **3 个方向**，每个方向包含：名称、关键词、色板倾向、排版/布局特征、适合场景、主要风险。方向应有明显差异，例如“清透数据工作台 / 温暖服务门户 / 高对比创意品牌”，而不是三个换色方案。等待用户选择后再实施。

### 2. 识别项目并复用现有系统

先查看项目的入口、路由、页面目录、全局样式和相邻页面。尽量复用已有组件，不要重复造轮子。

#### Vue3 项目

适用目录：`E:\me\doudou-vue3`。

- 技术栈为 Vue 3 + JavaScript + Vite + Element Plus + Pinia + Vue Router + Sass。
- 先看 `package.json`、`src/main.js`、`src/router/index.js`、`src/App.vue` 和相邻 `src/views` 页面。
- 优先复用 `src/BaseComponent` 的 `BaseForm`、`BaseTable`、`BaseEchart`，以及 `src/components/HsjComponent` 的 `PageContent`、`PageDialog`、`PageSearch` 等。
- 遵循 `src/assets/css` 中的 Sass tokens、Element Plus CSS 变量、暗色主题和现有布局；不要为了单页引入新的 UI 框架。
- 新页面涉及权限时，先说明路由是静态还是动态权限路由，并按项目现有模式接入。

#### UniApp 项目

适用目录：`E:\me\doudou-uniapp`。

- 技术栈为 Vue 3 + Pinia + uni-app，目标可能是 H5、App、小程序；平台差异必须考虑。
- 先看 `manifest.json`、`main.js`、`App.vue`、`pages.json` 和目标页面。
- 页面放入 `pages` 对应业务目录，路由与 tabBar 在 `pages.json` 中维护；新增页面同步加入配置。
- 优先复用 `uni_modules` 中已有 uni-ui 组件、`components` 中业务组件及 ColorUI 工具类。
- 遵循 `uni.scss`、`static/scss/global.scss`、ColorUI 与 `iconfont.css`；平台特有代码使用条件编译（如 `#ifdef H5`、`#ifdef MP`），不要假定浏览器 API 在 App/小程序可用。
- 仓库没有可靠的 npm scripts 时，不要编造构建命令；说明需要 HBuilderX 或用户提供的 uni-app CLI 配置。

### 3. 建立页面设计方案

在动手前用简短清单记录：

1. 页面目标与主要用户任务。
2. 信息架构和组件树。
3. 桌面/移动端断点与关键重排规则。
4. 色彩、字体层级、间距、圆角、阴影和图标策略。
5. 空状态、加载、错误、禁用、成功反馈等状态。
6. 哪些部分复用现有组件，哪些部分需要新增。

优先先做结构正确的最小可用版本，再打磨视觉。避免只做一张静态“海报”：按钮、筛选、标签页、表单和导航应有真实反馈，不能让用户点击后毫无变化。

### 4. 实现

- 先修改最少的必要文件；保持周边代码的命名、注释密度、缩进和样式写法。
- 将重复内容抽为数据或组件，避免复制大量相似模板。
- 使用项目已有图标、字体和资源；没有合适资源时用中性图形或文字占位，不抓取不明来源的远程资产。
- 保证可访问性基础：语义化元素、可见焦点、足够对比度、表单标签、键盘可操作性和合理的 aria 属性。
- 保证响应式：不出现横向溢出；触控目标足够大；长文案、空列表和窄屏下仍可读。
- 涉及图表时，遵循现有 `BaseEchart` 或项目图表模式；为坐标轴、图例、空数据和暗色主题提供处理。

### 5. 运行与验证

#### Vue3

优先在 `E:\me\doudou-vue3` 执行：

```text
pnpm install       # 依赖未安装时执行
pnpm dev           # 开发验证
pnpm build:prod    # 生产构建验证
```

使用浏览器检查目标页面，并至少覆盖：初始状态、核心点击/输入流程、窄屏视口、暗色主题（若项目启用）、刷新/路由返回。检查控制台错误和明显的网络失败。后端 API 未启动时，将接口问题与前端渲染问题分开报告。

#### UniApp

根据用户环境通过 HBuilderX 或已有 uni-app CLI 运行。至少验证 H5；如果目标是 App/小程序，说明尚未验证的平台并检查条件编译分支。H5 配置通常使用 9090、hash 路由和相对 base，但以仓库配置为准。

不要声称“已验证”而没有实际运行；若工具或环境不可用，明确列出未完成项及用户可执行的验证步骤。

### 6. 交付说明

完成后用中文简要报告：

- 修改/新增的文件及作用。
- 实现的页面结构、主要交互和响应式行为。
- 运行过的命令或浏览器检查；成功、失败和未验证项。
- 若使用了中性占位内容或因安全边界未复制某些元素，明确说明。
- 如有后续建议，按优先级列出，不要掩盖已知问题。

## 输出风格

先给结论和下一步，再给必要细节。设计选择要解释“为什么适合目标用户/项目”，而不是只罗列颜色和组件名称。对于尚未确认的需求使用选项提问，不要假装已获得授权或已完成运行验证。
