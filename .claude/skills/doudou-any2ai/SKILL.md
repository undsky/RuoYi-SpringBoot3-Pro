# Any2AI：任意文件转 AI 友好文本

按文件类型分派到对应的转换服务，拿回可以直接喂给模型的文本。你负责识别类型、挑参数、
把结果交给用户；转换在服务端跑。

## 第一步：按类型分派

先看扩展名，决定走哪条链路。别凭文件名猜内容，扩展名是唯一可靠的依据。

| 文件类型         | 扩展名                                                                                                                                   | 链路               | 怎么做                     |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------ | -------------------------- |
| 🎙️ 音视频        | `.mp3` `.wav` `.m4a` `.aac` `.flac` `.ogg` `.opus` `.mpeg` `.mpga` `.mp4` `.mov` `.mkv` `.avi` `.webm` `.flv` `.wmv` `.m4v` `.ts` `.3gp` | whisper 听录       | 见下方 **音视频转字幕**    |
| 📄 文档 & 电子书 | `.doc` `.docx` `.docm` `.xls` `.xlsx` `.xlsm` `.xlsb` `.ppt` `.pptx` `.pptm` `.pps` `.ppsx` `.pot` `.epub` `.rtf` `.csv` `.odt` `.ods` `.odp` | anydoc 转 Markdown | 见下方 **文档转 Markdown** |
| 🖼️ 图片 & PDF    | `.png` `.jpg` `.jpeg` `.webp` `.bmp` `.tiff` `.gif` `.pdf`                                                                               | PaddleOCR          | 见下方 **OCR**             |

**不在列表里的扩展名直接跳过**，处理完后总结时列出跳过的文件（带原因：格式不支持）。
不要硬塞给某条链路 —— 走错链路的报错指向"探测不到音轨"这类无关方向，反而难查。

一次给多个文件，先按类型分组 —— 不同类型分别处理，所有文件逐个转换。

## 三个脚本的共同约定

`whisper.py`、`anydoc.py`、`paddleocr.py` 这三条都适用：

`scripts/` 是相对**本技能目录**的路径，不是用户的工作目录 —— 实际执行时用技能目录的
绝对路径拼出来。

用 `python3`，不要用 `python`。很多机器上 `python` 还指向 Python 2，脚本里有中文
会直接报 `SyntaxError`。Windows 上 `python3` 不通就试 `py -3`。

**正文走 stdout，进度和元信息走 stderr。** 所以 `|` 管道拿到的是纯字幕 / 纯 Markdown，
不用再洗一遍。出错时也一样，诊断信息不会污染正文。

三个脚本都只用标准库，装完 Python 就能跑，不需要 pip install。

### 产物存哪里

转换结果默认保存在项目根目录下的 `resources/any2ai/` 目录中，默认文件名追加本地时间戳（年月日时分秒），例如 `resources/any2ai/口播-20260819153012.srt`：

| 场景       | 怎么执行                                                                                     |
| ---------- | -------------------------------------------------------------------------------------------- |
| **默认**（未明确指定） | 默认输出到 `resources/any2ai/`，文件名追加 `-年月日时分秒`（如 `-20260819153012`），执行前告知用户将写入该位置 |
| 自定义目录 | 用户明确给出了存放路径（如 "存到 out/"），则按用户指定路径保存，目录不存在会自动建             |
| 不用保存   | 用户明确说明 "不用存" 或 "我就看看内容"，则不传 `-o`，正文只走 stdout，内容留在对话里         |

```bash
# 默认情况（用户未明确指定路径，默认存入 resources/any2ai/）
python3 scripts/whisper.py data/口播.mp4 -l Chinese -o resources/any2ai/口播-20260819153012.srt

# 用户指定了自定义目录
python3 scripts/whisper.py data/口播.mp4 -l Chinese -o out/口播.srt

# 用户明确表示"不用存" —— 不给 -o，正文进 stdout
python3 scripts/whisper.py data/口播.mp4 -l Chinese
```

## 音视频转字幕

```bash
# 本地文件 → 中文 SRT
python3 scripts/whisper.py 录音.m4a --language Chinese --prompt "以下是普通话的句子。"

# 本地文件 → 纯文本
python3 scripts/whisper.py 播客.mp3 --format txt

# 存成文件（默认存到 resources/any2ai/，或用户指定路径）
python3 scripts/whisper.py media/talk.mp4 -l English \
  -o resources/any2ai/talk-20260819153012.srt
```

### 选参数

| 参数                | 什么时候需要动                                                                                                                          |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `--language` / `-l` | **值得花心思填。** `auto` 会先跑一次语种检测，慢且偶尔认错（中文认成粤语/日语的情况见过）。听得出是中文就填 `Chinese`，英文填 `English` |
| `--format` / `-f`   | 用户要字幕文件 → `srt`（默认）；要拿内容去做摘要、翻译、写文案 → `txt`，省掉满屏时间码                                                  |
| `--prompt`          | 中文素材传 `以下是普通话的句子。`，标点和数字会明显规整。有专有名词（人名、产品名、术语）也塞这里，能提高命中率                         |
| `--task`            | 只有用户明确要"翻成英文"时才用 `translate`。要译成其他语言，先 `transcribe` 拿原文再自己译                                              |
| `--model`           | **留空。** 服务端预置了 medium 权重，换别的可能触发模型下载并在离线环境失败                                                             |
| `--threads`         | 别动，默认 4                                                                                                                            |
| `-o`                | 产物输出路径。默认存到 `resources/any2ai/` 且文件名追加 `-年月日时分秒`；用户指定路径则按指定路径；用户明确说不存则不传。见 **产物存哪里**         |

`--json` 会打印完整响应（含 media 时长、编解码、服务端产物路径等元信息）。平时不用，
它会把正文塞进 JSON 字符串，转义后可读性差。

### 文件大小限制

文件走本地 multipart 上传，**上限 100MB**。超了就别硬试，可以用 ffmpeg 抽音轨压一版（`ffmpeg -i big.mp4 -vn -ac 1 -ar 16000 small.wav`，纯语音识别根本不需要视频轨和高码率）。

### 要等多久

CPU 推理，实测耗时约为**音频时长的 0.72–0.95 倍**：30 秒的口播约 25 秒，
1 小时的会议录音约 45–55 分钟。

开跑前先告诉用户大概要等多久，别让人以为卡死了。长音频不要设短超时 —— 脚本默认
等待 3600 秒。

### 出错了怎么读

失败时脚本会打出 `阶段` / `详情` / `提示` 三行，`阶段`直接指向问题归属：

| 阶段       | 含义                      | 怎么办                                                                                 |
| ---------- | ------------------------- | -------------------------------------------------------------------------------------- |
| `validate` | 参数不合法                | 按提示改参数，重试没意义                                                               |
| `nospeech` | 跑通了但一句话都没识别到  | 文件里确实没人说话（纯音乐、静音、只有环境音）。**这不是故障**，如实告诉用户，不要重试 |
| `probe`    | 探测不到音轨              | 文件损坏、压根没有音频流，或者分派走错了链路                                           |
| `exec`     | 抽音轨或 whisper 本身挂了 | 服务端处理失败，把`详情`原样给用户                                                     |

`连不上 API` 说明服务未启动或地址不对，见 **服务地址**。

出错时把`阶段`和`详情`如实转述给用户 —— 这些信息是专门为了能被诊断才做出来的，
含糊成"转写失败了"就白费了。

## 文档转 Markdown

```bash
# 本地文件 → 直接看内容
python3 scripts/anydoc.py 报告.docx

# 存成文件（默认存到 resources/any2ai/，或用户指定路径）
python3 scripts/anydoc.py 报表/财报.xlsx -o resources/any2ai/财报-20260819153012.md

# 大表格截断，避免撑爆上下文
python3 scripts/anydoc.py 明细.csv --max-chars 20000
```

### 选参数

| 参数              | 什么时候需要动                                                                                                                                                  |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--format` / `-f` | **通常留空。** anydoc 按文件内容判定，比扩展名可靠。只有一种情况要填：文件没有扩展名 |
| `--max-chars`     | 大表格喂模型前用。截断只影响返回的内容，服务端产物始终是全文                                                                                                    |
| `-o`              | 产物输出路径。默认存到 `resources/any2ai/` 且文件名追加 `-年月日时分秒`；用户指定路径则按指定路径；用户明确说不存则不传。见 **产物存哪里**         |
| `--json`          | 要服务端产物路径、字节数这些元信息时用。平时不用                                                                                                                |

`--format` 填错**不会报错** —— anydoc 会按你指定的格式硬解，返回 200 和一堆乱码。
所以拿不准就别填，让它自己判定。

### 要等多久

纯 CPU 解析、不联网，快得多：小文档几十毫秒，大 CSV 几百毫秒。默认超时 300 秒，够用。

### 出错了怎么读

和音视频一样打 `阶段` / `详情` / `提示` 三行：

| 阶段          | 含义                        | 怎么办                                                                                                                                            |
| ------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `validate`    | 参数不合法                  | 按提示改参数，重试没意义                                                                                                                          |
| `unsupported` | anydoc 认不出这个文件       | **没有文字层**（扫描件、纯图片 PDF、图片本身）。不是故障 —— 改走 OCR 链路即可                                                                    |
| `convert`     | anydoc 起不来或解析中途失败 | 文件损坏、加密、或格式指定错了。把`详情`原样给用户                                                                                                |

**一个容易漏的坑：成功了但内容是空的。** anydoc 对残缺文档采取"尽量恢复"策略，
转不出东西也会正常退出（HTTP 200）。脚本会在 stderr 明确警告，看到就如实告诉用户
"这个文档没有可提取的文字"，别把空结果当成"文档内容就是空的"讲。文档里有图但转出来
是空的，说明它其实是扫描件，该走 OCR。

## OCR

```bash
# 本地图片 → 直接看内容
python3 scripts/paddleocr.py screenshot.png

# 英文图片识别
python3 scripts/paddleocr.py invoice_en.jpg -l en

# 存成文件（默认存到 resources/any2ai/，或用户指定路径）
python3 scripts/paddleocr.py scan.png -o resources/any2ai/scan-20260819153012.txt

# PDF 扫描件（自动先尝试 anydoc 提取，失败时降级 OCR）
python3 scripts/paddleocr.py scan.pdf
```

### 选参数

| 参数            | 什么时候需要动                                                                                                            |
| --------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `--lang` / `-l` | 默认 `ch`（中文）。识别英文或特定外文素材时指定（支持 `en` `chinese_cht` `japan` `korean` `french` `german` 等 15 种）    |
| `-o`            | 产物输出路径。默认存到 `resources/any2ai/` 且文件名追加 `-年月日时分秒`；用户指定路径则按指定路径；用户明确说不存则不传。见 **产物存哪里**         |
| `--json`        | 要服务端路径、字符数、文本框数等元信息时用。平时不用                                                                      |
| `--base`        | 单次覆盖 API 地址，不改配置文件                                                                                           |
| `--timeout`     | 默认 300 秒，通常够用                                                                                                     |

### 要等多久

- **图片（单张）**：0.5–3 秒（取决于分辨率和文本密度）
- **PDF（扫描件）**：每页约 2–5 秒
- **PDF（有文字层）**：几十到几百毫秒（自动走快速提取）
- **首次调用**：模型加载需额外 5–10 秒（服务冷启动时）

开跑前告诉用户大概要等多久。

### 出错了怎么读

和文档转换一样打 `阶段` / `详情` / `提示` 三行：

| 阶段       | 含义                 | 怎么办                                             |
| ---------- | -------------------- | -------------------------------------------------- |
| `validate` | 参数不合法           | 按提示改参数，重试没意义                           |
| `save`     | 保存上传文件失败     | 磁盘满、权限问题，把`详情`原样给用户               |
| `ocr`      | OCR 识别失败         | 文件损坏、格式不支持、内存不足，把`详情`原样给用户 |

出错时把`阶段`和`详情`如实转述给用户，不要含糊成"识别失败了"。

## 服务地址

三条链路共用同一个后端服务实例。地址按下面的顺序查找，命中即停：

1. `--base` 参数（单次覆盖）
2. 环境变量 `doudou_any2api_url`
3. **项目根**的 `.env` 里的 `doudou_any2api_url` —— 从当前工作目录往上找，
   遇到 `.agents` / `.claude` 就认作项目根
4. **技能目录**的 `.env`（随仓库分发，默认写的是 `http://localhost:5678`）
5. 兜底 `http://localhost:5678`

技能目录自带 `.env`，默认配置为本机服务。要改地址，优先用前三种方式：

```bash
# 任选一种，都不用动技能自带的 .env
export doudou_any2api_url=http://192.168.1.10:5678
echo 'doudou_any2api_url=http://192.168.1.10:5678' >> .env   # 在用户自己的项目根
```
